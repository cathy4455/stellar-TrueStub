## Intentional — Next.js conventions

`page.tsx`, `route.ts`, and `layout.tsx` are **required** by Next.js App Router
to be named exactly that in every route segment.  These are not duplicates in
any meaningful sense.

Same for `index.ts` (barrel re-exports) and `types.ts` (per-module type files).

## Intentional — `tw-blocks` dialog / form / button decomposition

`ApproveMilestone`, `ChangeMilestoneStatus`, `FundEscrow`, and related hooks
(`useApproveMilestone`, `useChangeMilestoneStatus`, `useFundEscrow`) exist in
multiple sub-directories (`button/`, `dialog/`, `form/`) because the
TrustlessWork blocks pattern separates trigger, dialog shell, and form logic
into co-located files of the same component name.  This is intentional by
design.  The `schema.ts` and `useInitializeEscrow.ts` files follow the same
pattern across `single-release/` vs `multi-release/` variants.

**Verdict: intentional — no action needed.**
